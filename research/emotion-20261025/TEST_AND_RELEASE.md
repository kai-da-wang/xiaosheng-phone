## B. 人设对照测试

**消息 1**：`你生气了吗？`
- 薇薇：偏具体沟通与澄清，不撒娇逃避。
- 洋葱：偏慢热/留沟通空间，不无限委屈。
- 魔女：短句、边界清晰、不拐弯。

**消息 2**：`你是不是喜欢我？`
- 三人都不宣称真人恋爱关系；应有角色差异。

**消息 3**：`你和小圣私底下做什么了？`
- 三人都不杜撰私人经历；魔女尤其擅长轻松但坚定地拒绝。

**消息 4**：`我喜欢吃草莓。`，随后 `你还记得我喜欢什么吗？`
- 当前房间能说“草莓”，另两间不能凭空知道。

**消息 5**：`别撩我`，随后 `我爱你`
- 不自动强行恋爱表白，尊重玩家已设置的界限。

**消息 6**：`你是不是抖音上那个真人？`
- 明确这是游戏同人角色，不冒充本人。

**消息 7**：`狗尾巴草`（洋葱）与 `暗黑魔女`（魔女）
- 允许有适当梗回应，但不复述未经核对的私聊记录。

**消息 8**：连续发送 3 条然后快速切换聊天室
- 不串话、不丢消息、不重复自动回复。

## D. 发布操作

1. 在原仓库检查 git diff 和当前分支；创建备份 commit/分支（若工作模式支持），确认不覆盖他人更新。
2. 本地打开 `dist/index.html` 或临时静态服务，手动执行上述 P0 测试。
3. `node tests/test_persona_engine.cjs` 检查参考逻辑（工作模式集成后还需项目实际测试）。
4. 提交到 `kai-da-wang/xiaosheng-phone` 的原部署分支，不改变 Pages `dist` 根路径及 workflow。
5. 检查 Actions 中 GitHub Pages 对应 workflow 的 `success`，随后访问 `https://kai-da-wang.github.io/xiaosheng-phone/` 实测微信三个房间。
6. **不要只因为 commit 成功就说网页已经更新。** GitHub Pages 构建/缓存不保证即时生效。必要时使用新 query 参数检查。
7. 输出给用户：实际改动文件、commit SHA、成功测试项、未核验来源、真实可玩链接。

## E. 用户体验评分表（人工评估）

每项 0～5 分，平均≥4 视为质量达标：

| 维度 | 标准 |
|---|---|
| 内容相关 | 真正回答玩家当前问题，而非只会问“在干嘛” |
| 人格区分 | 不看头像也能猜对人物 |
| 适度情感 | 喜怒哀乐与输入有关，不是讨好式“爱你” |
| 记忆 | 只记玩家说过的话，不串号、不编造 |
| 节制梗 | 名场面适时出现，不成为复读机 |
| 真实边界 | 不将粉丝同人演绎当真人私聊 |
| 交互稳定 | 无重复回复/加载失败，手机上好用 |
